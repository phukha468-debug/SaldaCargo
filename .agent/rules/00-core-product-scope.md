# 00. Цели продукта, границы и заморозка платформ (PRO B2B SaaS)

## 1. Целевое позиционирование

- **SALDA (PRO)** — модульная облачная **Multi-tenant B2B SaaS ERP** для транспортных компаний, экспедиторов и СТО.
- **Модель деплоя:** основной фокус — облачный SaaS (единый кластер); архитектура должна поддерживать упаковку в **Docker** для опциональной Enterprise On-Premise установки.
- **Комплаенс (152-ФЗ РФ):** целевая инфраструктура — российский контур (Yandex Cloud / Selectel / Timeweb Cloud + Self-hosted Supabase / Managed PostgreSQL). Не закладывать жёсткие зависимости на проприетарные фичи зарубежных облаков.
- **ТК501 — Тенант №1:** историческая компания «ТК501 / ИП Нигамедьянов» является первым клиентом платформы, а не единственным.

## 2. Абсолютный запрет хардкода под одного клиента

Запрещено вшивать в код, миграции и конфигурации:

- Реквизиты юрлиц (ИНН, ОГРН, расчётные счета, ЭДО ID, адреса, телефоны, ФИО владельца).
- Названия брендов, домены (`tk501.ru`, `saldacargo`, `ancargo66`) и города по умолчанию («Верхняя Салда»).
- Конкретных контрагентов («ВСМПО-АВИСМА», «Геостройиндустрия»), госномера ТС, Wialon Unit ID, геозоны («Шайтанка») и UUID кошельков/категорий.
- Все клиентские настройки обязаны читаться из БД по `organization_id` (таблицы `organizations`, `legal_entities`, `organization_integrations`, `geofences`).

## 3. Заморозка нативного Android (`apps/android`)

> **СТРОГОЕ ПРАВИЛО:** Директория `apps/android/` **полностью заморожена** на весь период трансформации до PRO-версии.

- **Запрещено** вносить изменения, добавлять фичи, исправлять баги или обновлять зависимости внутри `apps/android/`.
- Все новые фичи, рефакторинг и багфиксы выполняются строго в **`apps/web`** (Web Dashboard), **`apps/miniapp`** (MAX MiniApp) и общих пакетах **`packages/*`**.
- Возврат к единому нативному Android-приложению (с выбором компании и динамическим брендингом) произойдёт только после стабилизации PRO API по явному решению владельца.

## 4. Биллинг и тарифные ограничения (проектировать заранее)

- Подписка комбинированная: **пакет активных модулей + лимит активных ТС**.
- Все новые доменные операции создания ТС/объектов должны учитывать возможность проверки тарифных квот и статуса подписки (включая `read_only` режим при просрочке оплаты).
