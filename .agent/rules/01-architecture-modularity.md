# 01. Архитектура, Модульность и Стандарты Кода

## 1. Модульный конструктор (Feature Flags & Module Isolation)

Продукт продаётся по модульному принципу. Бизнес-модули обязаны быть изолированы друг от друга:

- `transport` — Транспортная компания (рейсы, заявки, автопарк, ревью, Wialon/GPS).
- `garage` — СТО / Гараж (заказ-наряды, клиентские авто, регламенты ТО, каталог работ).
- `expeditor` — Экспедирование / АТИ (договоры-заявки, сторонние перевозчики).
- `warehouse` — Склад запчастей и материалов.
- `payroll` — Персонал, табель и расчёт ЗП.
- `finance` — Финансы, кошельки, банк, дебиторка, платёжный календарь.

**Правила изоляции модулей:**

- Доступ к любому модулю контролируется через **Feature Flags на уровне организации** (`organization_modules` / `enabled_modules`) — как в UI (скрытие разделов меню), так и в API-guard (`requireModule('garage')`).
- Модуль не должен падать, если соседний модуль отключён у организации (например, клиент купил только «СТО / Гараж» без «Транспортной компании»).

## 2. Единый слой бизнес-логики (Запрет дублирования Web ↔ MiniApp)

- **Старое правило «открой зеркальный роут в другом приложении и скопируй правку» — ОТМЕНЕНО.**
- Вся нетривиальная бизнес-логика, расчёты и кросс-табличные мутации (финансы рейсов, кошельки, сверки, расчёт ЗП, документы) размещаются **один раз** в `packages/service` или профильных доменных пакетах (`packages/payroll`, `packages/identity`, `packages/shared`).
- API-роуты в `apps/web/app/api/**` и `apps/miniapp/app/api/**` являются тонкими адаптерами: валидация → авторизация/RBAC/модуль → вызов сервиса из `packages/*` → HTTP-ответ.
- Не нарушать направление зависимостей: `apps/*` → `packages/*` → `@saldacargo/shared-types`.

## 3. Абстрактные адаптеры внешних интеграций

Никаких прямых вызовов конкретных провайдеров из бизнес-логики или UI. Внешние сервисы подключаются через интерфейсы в `packages/service/src/providers/`:

- `GpsProvider` (текущая реализация: Wialon; задел: ГЛОНАССSoft, АвтоГРАФ).
- `BankProvider` (текущая реализация: Т-Банк; задел: Точка, Сбер, Альфа).
- `FuelCardProvider` (текущая реализация: ОПТИ-24).
- `MessengerProvider` (MAX Bot, Telegram Bot, Email/Resend).
- `AccountingExporter` (задел: 1С, ЭДО).

## 4. Строгая типизация и чистота кода

- **Запрещено добавлять новые `: any`, `as any` и `eslint-disable ... no-explicit-any`.** Старое правило `as any` на `.from()` — **ОТМЕНЕНО**.
- Использовать сгенерированные типы БД (`@saldacargo/shared-types` в `packages/types/src/database.types.ts`).
- Не создавать новые God-файлы: целевой лимит для новых компонентов и модулей — **≤ 400 строк**; разделять UI, хуки и API-клиенты по `features/<module>/`.
- **Next.js 16 (Breaking Changes):** проект работает на Next.js 16 + React 19 + Tailwind CSS 4. Перед использованием API App Router / Middleware / Cookies сверяться с актуальной документацией в `node_modules/next/dist/docs/`.
- Серверный код не должен полагаться на локальный `python` / системные утилиты (совместимость с Node.js/Docker/Serverless).
